# 智能体育场馆预约与分配系统 V1.0

## 用户使用手册

---

## 第一章 软件概述

### 1.1 软件背景

随着我国高校体育事业的蓬勃发展，在校师生对体育场馆的使用需求日益增长。然而，传统的人工预约、微信群接龙、现场排队等方式存在效率低下、信息不透明、场地分配不均等问题。特别是在高峰时段，热门场地（如羽毛球场、篮球场）往往供不应求，而部分冷门场地却长期闲置，造成资源配置失衡。

本系统针对上述痛点，设计并实现了一套面向高校体育场馆的智能化预约与动态分配管理系统。系统采用 B/S（浏览器/服务器）架构，基于 Python Flask 框架开发，前端采用响应式设计，支持 PC 端与移动端浏览器访问。系统核心创新在于引入模拟退火算法与神经网络模型，实现场地资源的智能优化分配。

### 1.2 软件用途

本软件主要应用于以下场景：

- **高校体育场馆管理**：为大学体育馆、活动中心提供在线预约、智能分配、数据统计等功能。
- **社区运动中心**：适用于社区级体育设施的资源调度与管理。
- **企事业单位文体中心**：为企业内部体育设施提供规范化预约管理。

### 1.3 软件目标

1. 提供便捷的在线预约渠道，替代传统人工登记方式。
2. 通过智能算法实现场地资源的公平、高效分配。
3. 建立用户信用体系，减少占场不用的资源浪费现象。
4. 为场馆管理者提供数据可视化与决策支持工具。

### 1.4 术语定义

| 术语 | 说明 |
|------|------|
| 场地 | 体育场馆中的具体运动区域，如羽毛球场1号、篮球场A区等 |
| 预约 | 用户在系统中选定场地和时段，提交使用申请 |
| 签到 | 用户在实际使用场地前，在系统中确认到场 |
| 匹配度 | 系统计算的用户偏好与分配场地之间的契合程度，范围为0-100% |
| 模拟退火 | 一种全局优化算法，通过模拟物理退火过程寻找近似最优解 |
| 神经网络 | 一种机器学习模型，本系统用于预测用户对场地的满意度 |

**步骤一：环境准备**

确保服务器已安装 Python 3.8 或更高版本。可通过命令行输入以下命令验证：

```
python --version
```

**步骤二：安装依赖**

进入项目目录，执行以下命令安装所需依赖库：

```
pip install flask numpy torch
```

**步骤三：初始化数据库**

运行数据库初始化脚本，创建系统所需的表结构：

```
python create_demo_db.py
```

**步骤四：启动服务**

执行以下命令启动 Flask 开发服务器：

```
python app.py
```

启动成功后，命令行将显示服务地址，如：

```
Running on http://192.168.1.35:5000
```

**步骤五：访问系统**

在客户端浏览器中输入服务器地址，即可访问系统首页。

## 第三章 系统功能详解

### 3.1 系统架构

本系统采用经典的三层架构设计：

**表示层（前端）**：负责用户界面展示与交互，采用 HTML5 + CSS3 + JavaScript 技术栈，使用 Bootstrap 栅格系统实现响应式布局。

**业务逻辑层（后端）**：基于 Flask 框架实现 RESTful API，处理用户请求、业务逻辑计算、数据校验等。

**数据访问层**：采用 SQLite 轻量级数据库，存储用户信息、场地信息、预约记录等数据。

### 3.2 用户端功能模块

#### 3.2.1 用户注册与登录

**功能描述**：
新用户通过注册页面填写用户名、密码完成账号创建。系统支持普通用户与管理员两种角色。普通用户通过常规注册流程创建账号；管理员需在注册时输入邀请码（如 COURT2024），通过验证后获得管理员权限。

**操作流程**：
1. 打开系统首页，点击"注册"按钮。
2. 填写用户名（6-20位字母数字组合）、密码（至少6位）。
3. 如需注册管理员账号，在邀请码栏输入有效邀请码。
4. 点击"确认注册"，系统校验通过后创建账号。
5. 返回登录页面，输入用户名和密码，点击"登录"进入系统。

**注意事项**：
- 用户名不可重复，系统会自动检测。
- 密码采用加密存储，保障用户信息安全。
- 登录状态通过 Session 维持，默认有效期为浏览器关闭前。

#### 3.2.2 场地浏览与智能推荐

**功能描述**：
登录后进入"场地看板"页面，系统以卡片或表格形式展示所有可用场地。每个场地显示名称、类型（羽毛球/篮球/乒乓球/足球）、位置、容量、实时状态（空闲/预约中/使用中）等信息。

系统会根据用户的历史预约记录，自动计算用户偏好（偏好的场地类型、常用时段），并在"为你推荐"区域展示匹配度最高的场地。

**操作流程**：
1. 登录后自动进入场地看板页面。
2. 浏览场地列表，可点击筛选按钮按类型过滤。
3. 查看"为你推荐"区域，系统推荐的场地带有"推荐"标签。
4. 点击场地卡片，可查看该场地的详细信息和未来7天的可预约时段。

#### 3.2.3 在线预约

**功能描述**：
用户选择目标场地和时段后，提交预约申请。系统自动检查冲突（该时段是否已被预约、用户是否已有冲突预约），校验通过后锁定场地，预约状态变为"预约中"。

**操作流程**：
1. 在场地看板点击目标场地的"预约"按钮。
2. 在弹出的预约窗口中选择日期和时段。
3. 系统实时显示该时段的可预约状态（绿色=可约，红色=已满）。
4. 点击"确认预约"，系统执行冲突检测。
5. 预约成功，弹出提示框，场地状态更新为"预约中"。

**预约规则**：
- 每个用户在同一时段只能预约一个场地。
- 预约成功后需在15分钟内完成签到，否则系统自动释放场地。
- 用户可主动取消未签到的预约。

#### 3.2.4 我的预约与签到管理

**功能描述**：
用户可在"我的预约"页面查看所有历史预约记录，包括进行中的预约、已完成的预约和已取消的预约。对于"预约中"的订单，用户可以进行签到或取消操作。

**操作流程**：
1. 点击导航栏"我的"进入个人中心。
2. 查看"我的预约"列表，按时间倒序排列。
3. 对于状态为"预约中"的订单：
   - 点击"签到"按钮，状态变为"已使用"。
   - 点击"取消"按钮，状态变为"已取消"，场地释放。
4. 对于已完成的预约，可查看分配场地的匹配度评分。

#### 3.2.5 个人中心

**功能描述**：
用户可在个人中心查看和修改个人信息，包括偏好设置（偏好场地类型、偏好时段）、查看信用积分等。

### 3.3 管理端功能模块

#### 3.3.1 全局优化（核心功能）

**功能描述**：
管理员进入"全局优化"页面后，可执行智能优化分配。系统调用模拟退火算法，综合考虑所有用户的场地偏好、时段偏好，计算全局最优的场地分配方案。优化结果以卡片形式展示，显示每个用户分配的场地及匹配度。

**操作流程**：
1. 管理员登录后，点击导航栏"全局优化"。
2. 页面展示当前所有待分配用户的预约请求。
3. 点击"执行全局优化"按钮，系统运行模拟退火算法。
4. 等待算法执行完成（通常3-5秒）。
5. 页面刷新，展示优化后的分配结果，包括：
   - 每个用户分配的场地名称和时段
   - 理论匹配率（算法计算的最优值）
   - 实际匹配率（当前分配方案的满意度）
   - 分配状态（成功/冲突/未匹配）

**参数设置**：
管理员可调整算法参数以平衡计算时间与优化效果：
- 初始温度：控制算法初期接受劣解的概率
- 迭代次数：影响搜索深度
- 冷却系数：控制温度下降速度

#### 3.3.2 用户管理

**功能描述**：
管理员可查看系统内所有注册用户的信息，包括用户名、角色、预约次数、信用积分、偏好分析等。支持按条件筛选和搜索。

#### 3.3.3 场地管理

**功能描述**：
管理员可维护场地信息，包括新增场地、编辑场地属性（名称、类型、容量、位置）、启用/禁用场地等。

#### 3.3.4 数据统计

**功能描述**：
系统提供可视化数据看板，展示以下统计信息：
- 场地使用率趋势图（按日/周/月统计）
- 各类型场地热门时段分析
- 用户活跃度排行
- 预约取消率分析

### 3.4 算法引擎模块

#### 3.4.1 模拟退火算法

**算法原理**：
模拟退火算法（Simulated Annealing, SA）是一种模拟物理退火过程的随机优化算法。算法从高温状态开始，允许以一定概率接受劣解，随着温度逐渐降低，接受劣解的概率减小，最终收敛到全局最优或近似最优解。

**本系统实现**：
- 解空间：所有用户到场地的分配方案
- 能量函数（适应度）：综合类型匹配、时段匹配、楼层匹配的加权评分
- 扰动方式：随机交换两个用户的分配或重新分配一个用户
- 终止条件：达到最大迭代次数或温度降至阈值

#### 3.4.2 神经网络满意度预测

**算法原理**：
系统采用多层感知机（MLP）神经网络，输入用户特征（偏好类型、历史预约次数等）和场地特征（类型、时段、空闲率等），输出用户对该场地的满意度预测分数（0-1之间）。

**模型结构**：
- 输入层：11维特征向量
- 隐藏层1：32个神经元，ReLU激活
- 隐藏层2：16个神经元，ReLU激活
- 输出层：1个神经元，Sigmoid激活

**训练方式**：
使用历史预约数据作为训练集，已完成且签到的预约标记为正样本（满意度=1），取消或超时未签到的标记为负样本（满意度=0）。采用二分类交叉熵损失函数，Adam优化器进行训练。

#### 3.4.3 混合评分机制

系统最终采用规则评分与神经网络预测的混合机制：

```
最终匹配度 = α × 神经网络预测分 + (1-α) × 传统规则分
```

其中 α 为可调权重系数，默认取 0.6。该机制既保留了传统规则的可解释性，又引入了神经网络的学习能力。

## 第四章 操作指南

### 4.1 普通用户操作流程

**首次使用**：
1. 打开浏览器，输入系统地址。
2. 点击"注册"，填写信息创建账号。
3. 使用新账号登录。
4. 进入个人中心，设置偏好类型和偏好时段。
5. 浏览场地，点击推荐场地进行首次预约。
6. 到达场地后，在规定时间内完成签到。

**日常使用**：
1. 登录系统，查看"为你推荐"。
2. 选择心仪场地和时段，提交预约。
3. 在"我的预约"中管理订单。
4. 使用完毕后，系统自动记录为"已完成"。

### 4.2 管理员操作流程

**每日例行**：
1. 登录管理员账号。
2. 进入"全局优化"页面。
3. 查看当日待分配预约列表。
4. 点击"执行全局优化"，获取最优分配方案。
5. 检查分配结果，确认无异常后发布。
6. 查看数据统计页面，了解场地使用情况。

**每周分析**：
1. 导出本周预约数据。
2. 分析高峰期和低谷期。
3. 根据数据调整场地开放策略。

### 4.3 常见问题处理

**Q1：预约后无法签到？**
A：请检查是否在预约时段开始前15分钟内。若超过15分钟未签到，系统将自动取消预约。

**Q2：为什么推荐的场地不是我想要的？**
A：推荐基于您的历史预约记录。新用户因缺少历史数据，推荐可能不准确。请多使用几次系统，推荐效果会逐渐改善。

**Q3：全局优化后我的场地变了？**
A：全局优化是为了提升整体满意度，可能会调整个别用户的分配。如有特殊需求，请联系管理员。

**Q4：系统访问很慢？**
A：请检查网络连接。若使用高峰期访问，可能因并发用户较多导致延迟，建议错峰使用。

**Q5：如何修改个人偏好？**
A：进入"我的"页面，点击"偏好设置"，修改后保存即可。

## 第五章 系统维护

### 5.1 数据备份

建议管理员每周执行一次数据库备份：

1. 停止 Flask 服务（Ctrl+C）。
2. 复制数据库文件 `court_booking.db` 到备份目录。
3. 重新启动服务。

### 5.2 日志查看

系统运行日志输出在控制台，包含以下信息：
- 用户访问记录（IP、时间、请求路径）
- 错误堆栈信息
- 算法执行日志（迭代次数、最终得分）

### 5.3 异常处理

| 异常现象 | 可能原因 | 解决方法 |
|---------|---------|---------|
| 无法启动服务 | 端口被占用 | 修改 app.py 中的端口号，或关闭占用端口的程序 |
| 数据库错误 | 表结构损坏 | 运行 `create_demo_db.py` 重新初始化 |
| 算法执行超时 | 用户/场地数量过多 | 减少迭代次数或分批优化 |
| 前端显示异常 | 浏览器缓存 | 清除缓存或强制刷新（Ctrl+F5） |

### 6.4 算法参数配置说明

| max_iterations | 1000 | 500-5000 | 最大迭代次数 |
