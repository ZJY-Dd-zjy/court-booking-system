## 一、项目概述

### 1.1 项目背景

高校体育馆场地资源紧张，传统的人工预约方式存在以下问题：
- **信息不对称**：学生不知道哪些场地空闲，到现场才发现已满
- **排队冲突**：热门时段多人争抢同一场地，容易产生纠纷
- **资源浪费**：有人预约后不到场，场地空置却无法释放给他人
- **分配不均**：管理员手动分配难以兼顾所有人的偏好，满意度低

本项目旨在开发一套**智能化场馆预约系统**，通过在线预约、智能推荐、全局优化分配等功能，提升体育馆场地利用率，改善用户预约体验。

### 1.2 项目目标

| 目标层级       | 具体内容                                              |
|:--------------|:-----------------------------------------------------|
| 核心目标       | 实现完整预约流程：注册 → 登录 → 浏览场地 → 预约 → 签到 → 取消 |
| 进阶目标       | 基于用户偏好的智能推荐、基于模拟退火算法的全局最优分配            |
| 演示目标       | 8月29日前完成可运行的 Demo v1.0，支持 3 分钟完整演示            |

### 1.3 系统功能清单

- [x] 用户注册与登录（支持普通用户 / 管理员双角色）
- [x] 场地实时状态看板（空闲 / 预约中 / 占用 / 已超时）
- [x] 在线预约与时段选择
- [x] 我的预约管理（查看 / 签到 / 取消）
- [x] 智能场地推荐（基于历史偏好：类型 + 时段 + 楼层）
- [x] 管理员全局优化（模拟退火算法自动分配）
- [x] 超时自动释放（15分钟未签到自动释放场地）
- [x] 响应式布局（支持手机浏览器访问）
- [x] 并发安全（同一场地同一时段仅一人预约成功）

## 二、系统架构

### 2.1 技术架构图

系统采用经典的分层架构，自下而上分为五层：

**1. 用户层**
- PC 浏览器、手机浏览器、管理员端
- 通过 HTTP/JSON 协议与前端通信

**2. 前端层**
- `login.html`（登录注册）、`courts.html`（场地看板+推荐）
- `my.html`（我的预约）、`admin.html`（全局优化）
- 技术栈：HTML5 + CSS3 + JavaScript + Bootstrap 5

**3. 后端层**
- Flask RESTful API 服务，提供 11 个接口
- 核心接口：`/api/register`、`/api/login`、`/api/courts`、`/api/book`、`/api/optimize` 等
- 技术栈：Python 3 + Flask + flask-cors + SQLite3

**4. 数据层**
- `users` 表（用户）、`courts` 表（场地）、`reservations` 表（预约记录）
- SQLite 轻量级数据库

**5. 算法层**
- 模拟退火算法（Simulated Annealing）
- 输入：场地列表 + 用户列表 + 偏好数据
- 输出：最优分配方案 + 匹配率 + 运行时间
- 技术栈：Python + NumPy + random + math

**层间交互**：前端通过 `fetch API` 调用后端接口，后端通过 `SQL` 读写数据库，通过函数调用触发算法计算。

#### 数据库表结构

**users 表**：
```sql
CREATE TABLE users (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    username TEXT NOT NULL UNIQUE,
    password TEXT NOT NULL,
    role TEXT DEFAULT '普通用户'
);
```

**courts 表**：
```sql
CREATE TABLE courts (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    name TEXT NOT NULL,
    type TEXT NOT NULL,
    location TEXT,
    status TEXT DEFAULT '空闲'
);
```

**reservations 表**：
```sql
CREATE TABLE reservations (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    user_id INTEGER NOT NULL,
    court_id INTEGER NOT NULL,
    date TEXT NOT NULL,
    start_time TEXT NOT NULL,
    end_time TEXT NOT NULL,
    status TEXT DEFAULT '预约中',
    created_at TEXT,
    FOREIGN KEY (user_id) REFERENCES users(id),
    FOREIGN KEY (court_id) REFERENCES courts(id)
);
```

#### 核心逻辑

1. **并发安全**：预约接口使用 `BEGIN IMMEDIATE` 显式加锁，同一场地同一时段仅允许一人预约成功，冲突时返回 409 状态码。
2. **超时释放**：每次查询场地时检查"预约中"且超过 15 分钟未签到的记录，自动改为"已超时"并释放场地。
3. **推荐算法**：基于用户历史偏好加权推荐，维度包括类型匹配（50分）、楼层匹配（30分）、时段匹配（20分）。
4. **权限控制**：`Authorization` Header 携带 token，后端通过 `check_admin()` 验证管理员权限。

### 4.3 算法技术实现（zrd）

#### 算法选择：模拟退火（Simulated Annealing）

场馆分配问题是典型的**NP-hard 组合优化问题**。当用户数和场地数较大时，穷举搜索不可行。模拟退火算法通过概率突跳机制，在可接受时间内找到近似最优解。

#### 核心原理

**Metropolis 接受准则**：

```
P(accept) = 1,                        if f(j) >= f(i)
P(accept) = exp((f(j) - f(i)) / T),   if f(j) < f(i)
```

- 新解更好 → 一定接受
- 新解更差 → 以概率接受（概率随温度降低而减小）
- 高温时探索能力强，低温时局部精化

#### 目标函数

```
F(solution) = match_score - violation_penalty - no_pref_penalty
```

| 组成部分       | 计算方式               | 说明                  |
|:--------------|:----------------------|:---------------------|
| 匹配得分       | `10 × 类型匹配数 + 5 × 时间匹配数` | 鼓励满足用户偏好    |
| 违规惩罚       | `10 × 重复分配数 + 50 × I(存在违规)` | 惩罚场地重复分配    |
| 无偏好惩罚     | `2 × 有偏好但未匹配的用户数`       | 轻微惩罚未满足偏好   |

#### 参数配置（经实验确定）

```python
initial_temperature = 80
min_temperature     = 0.1
alpha               = 0.88
iterations_per_temp = 60
max_iterations      = 50000
max_no_improvement  = 1000
```

#### 实验结果

| 测试场景              | 匹配率 | 运行时间   | 违规数   |
|:---------------------|:------|:----------|:--------|
| 5场地  × 10用户     | ~90%  | < 0.3s    | 0       |
| 10场地 × 20用户     | ~88%  | < 0.5s    | 0       |
| 20场地 × 50用户     | ~87.5%| ~0.48s    | 0       |

算法满足 **2.5 秒超时限制**，场地唯一性约束最终收敛为 0 违规。

#### 收敛特征

- **探索阶段**（0~300 次迭代）：适应度快速上升
- **过渡阶段**（300~800 次迭代）：适应度缓慢上升
- **收敛阶段**（800~1500 次迭代）：适应度趋于稳定

- 深入理解了 Flask 框架的路由设计、请求处理、蓝图机制
- 掌握了 SQLite 数据库的事务控制和并发锁机制
- 学会了 RESTful API 设计规范和统一返回格式的重要性

**遇到的困难**：
- 并发预约冲突处理：初期未加锁导致两人同时预约同一场地成功，后通过 `BEGIN IMMEDIATE` 显式锁解决
- CORS 跨域问题：前端带自定义 Header 时触发预检请求失败，通过 `flask-cors` 配置解决

### 7.3 张瑞栋（算法）

**完成内容**：
- 设计并实现带时间维度和场地唯一性约束的模拟退火算法
- 设计目标函数（匹配得分 + 违规惩罚 + 无偏好惩罚）
- 完成参数敏感性实验，确定最优参数组合
- 输出收敛曲线分析，证明算法有效性

**学习收获**：
- 深入理解了模拟退火算法的 Metropolis 准则和冷却策略
- 学会了将实际问题抽象为数学优化问题（目标函数、约束条件）
- 掌握了参数调优的实验方法论

**遇到的困难**：
- 算法运行时间过长：初期 20场地50用户场景下运行超过 5 秒，后通过减少迭代次数、加入早停机制（连续 1000 步无改进则终止）优化至 0.5 秒以内
- 场地唯一性约束难以满足：初期违规数居高不下，后通过加大违规惩罚权重（50分额外惩罚）解决
